# V2 验证和业务逻辑

## 控制目标

本章旨在确保通过验证的应用满足以下高层目标：

* 应用接收的输入符合业务或功能预期。
* 业务逻辑流程按预期顺序逐步处理，不能被绕过。
* 业务逻辑包含限制和控制，用于检测并防止自动化攻击，例如连续进行小额转账，或一次添加一个好友直到添加一百万个。
* 高价值业务逻辑流程已考虑滥用场景和恶意行为者，并具备防范欺骗、篡改、信息泄露和权限提升攻击的保护措施。

## V2.1 验证和业务逻辑文档

验证和业务逻辑文档应清楚定义业务逻辑限制、验证规则，以及组合数据项之间的上下文一致性，明确应用需要实现的内容。

| # | 描述 | 级别 |
| :---: | :--- | :---: |
| **2.1.1** | 验证应用文档定义了输入验证规则，说明如何根据预期结构检查数据项的有效性。这可以是常见数据格式，例如信用卡号、电子邮件地址、电话号码，也可以是内部数据格式。 | 1 |
| **2.1.2** | 验证应用文档定义了如何验证组合数据项在逻辑和上下文上的一致性，例如检查城市与邮政编码是否匹配。 | 2 |
| **2.1.3** | 验证业务逻辑限制和验证的预期已记录在文档中，包括按用户维度以及应用全局维度的限制和验证。 | 2 |

## V2.2 输入验证

有效的输入验证控制会围绕应用预期接收的数据类型，强制执行业务或功能预期。这可以确保良好的数据质量，并减少攻击面。不过，当这些数据被用于其他组件，或用于输出展示时，它并不能取消或替代正确编码、参数化或净化的需要。

在此语境下，“输入”可能来自多种来源，包括 HTML 表单字段、REST 请求、URL 参数、HTTP 头字段、Cookie、磁盘文件、数据库和外部 API。

业务逻辑控制可能会检查某个输入是否为小于 100 的数字。功能预期可能会检查某个数字是否低于特定阈值，因为该数字控制某个循环执行多少次，过高的数字可能导致过度处理并引发潜在拒绝服务状况。

虽然标准没有明确强制要求使用模式验证，但对于使用 JSON 或 XML 的 HTTP API 或其他接口，它可能是实现完整验证覆盖的最有效机制。

请注意以下关于模式验证的要点：

* JSON Schema 验证规范的“已发布版本”被认为可用于生产环境，但严格来说并不算“稳定”。使用 JSON Schema 验证时，应确保与下列要求中的指导不存在缺口。
* 正在使用的任何 JSON Schema 验证库，也应在标准正式确定后持续监控，并在必要时更新。
* 不应使用 DTD 验证，并且应禁用框架的 DTD 求值，以避免 DTD 相关 XXE 攻击问题。

| # | 描述 | 级别 |
| :---: | :--- | :---: |
| **2.2.1** | 验证输入经过检查，以强制满足相应的业务或功能预期。应采用基于值、模式和范围允许列表的正向验证，或根据预定义规则将输入与预期结构和逻辑限制进行比较。对于 L1，可重点关注用于作出特定业务或安全决策的输入；对于 L2 及以上，则应适用于所有输入。 | 1 |
| **2.2.2** | 验证应用被设计为在可信服务层强制执行输入验证。虽然客户端验证可以提升易用性，也应鼓励使用，但不得依赖它作为安全控制。 | 1 |
| **2.2.3** | 验证应用能够根据预定义规则，确保相关数据项的组合是合理的。 | 2 |

## V2.3 业务逻辑安全

本节关注若干关键要求，确保应用以正确方式执行业务逻辑流程，并且不会受到利用应用逻辑和流程的攻击。

| # | 描述 | 级别 |
| :---: | :--- | :---: |
| **2.3.1** | 验证应用按照预期的连续步骤顺序为同一用户处理业务逻辑流程，不允许跳过任何步骤。 | 1 |
| **2.3.2** | 验证业务逻辑限制已按应用文档实现，以避免业务逻辑缺陷被利用。 | 2 |
| **2.3.3** | 验证在业务逻辑层使用事务，使业务逻辑操作要么整体成功，要么回滚到先前正确状态。 | 2 |
| **2.3.4** | 验证使用业务逻辑层锁定机制，确保有限数量资源（例如剧院座位或配送时段）不能通过操纵应用逻辑被重复预订。 | 2 |
| **2.3.5** | 验证高价值业务逻辑流程需要多用户审批，以防止未经授权或意外的操作。这可以包括但不限于大额资金转账、合同审批、访问涉密信息，或制造过程中的安全覆盖操作。 | 3 |

## V2.4 反自动化

本节包含反自动化控制，用于确保需要类人的交互，并防止过量自动化请求。

| # | 描述 | 级别 |
| :---: | :--- | :---: |
| **2.4.1** | 验证已具备反自动化控制，用于防止对应用功能的过量调用。这类调用可能导致数据外泄、垃圾数据创建、配额耗尽、突破速率限制、拒绝服务，或过度使用高成本资源。 | 2 |
| **2.4.2** | 验证业务逻辑流程要求符合真实人类操作的时间节奏，防止过快提交交易。 | 3 |
