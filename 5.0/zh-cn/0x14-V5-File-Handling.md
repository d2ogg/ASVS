# V5 文件处理

## 控制目标

文件使用可能给应用带来多种风险，包括拒绝服务、未授权访问和存储耗尽。本章包含用于处理这些风险的要求。

## V5.1 文件处理文档

本节包含一条要求：记录应用接受文件的预期特征。这是开发和验证相关安全检查的必要前提。

| # | 描述 | 级别 |
| :---: | :--- | :---: |
| **5.1.1** | 验证文档为每个上传功能定义了允许的文件类型、预期文件扩展名和最大大小（包括解包后的大小）。此外，文档还应说明如何向最终用户提供可安全下载和处理的文件，例如应用在检测到恶意文件时应如何响应。 | 2 |

## V5.2 文件上传和内容

文件上传功能是不可信文件的主要来源。本节概述相关要求，确保这些文件的存在、数量或内容不会损害应用。

| # | 描述 | 级别 |
| :---: | :--- | :---: |
| **5.2.1** | 验证应用只接受其能够正常处理的文件大小，避免造成性能下降或引发拒绝服务。 | 1 |
| **5.2.2** | 验证应用接受文件时，无论是单独文件，还是 zip 等归档文件中的文件，都会检查文件扩展名是否符合预期，并验证内容是否与扩展名所代表的类型一致。这包括但不限于检查初始“魔数”、执行图片重写，以及使用专门库进行文件内容验证。对于 L1，可仅关注用于作出特定业务或安全决策的文件。对于 L2 及以上，必须适用于所有被接受的文件。 | 1 |
| **5.2.3** | 验证应用在解压压缩文件（例如 zip、gz、docx、odt）之前，会根据允许的最大解压后大小和最大文件数量进行检查。 | 2 |
| **5.2.4** | 验证强制执行每个用户的文件大小配额和最大文件数，确保单个用户不能用过多文件或过大的文件填满存储空间。 | 3 |
| **5.2.5** | 验证应用不允许上传包含符号链接的压缩文件，除非确有特定需要（这种情况下必须强制执行可被符号链接指向的文件允许列表）。 | 3 |
| **5.2.6** | 验证应用拒绝像素尺寸超过最大允许值的上传图片，以防止像素洪泛攻击。 | 3 |

## V5.3 文件存储

本节包含若干要求，用于防止上传后的文件被不当执行、检测危险内容，并避免使用不可信数据控制文件存储位置。

| # | 描述 | 级别 |
| :---: | :--- | :---: |
| **5.3.1** | 验证由不可信输入上传或生成并存储在公共文件夹中的文件，在通过 HTTP 请求直接访问时，不会作为服务端程序代码执行。 | 1 |
| **5.3.2** | 验证应用为文件操作创建文件路径时，会使用内部生成或可信数据，而不是用户提交的文件名；如果必须使用用户提交的文件名或文件元数据，则必须进行严格验证和净化。这样做是为了防范路径遍历、本地或远程文件包含（LFI、RFI）以及服务端请求伪造（SSRF）攻击。 | 1 |
| **5.3.3** | 验证服务端文件处理（例如文件解压）会忽略用户提供的路径信息，以防止 zip slip 等漏洞。 | 3 |

## V5.4 文件下载

本节包含在提供文件下载时降低风险的要求，包括路径遍历和注入攻击风险，也包括确保文件不包含危险内容。

| # | 描述 | 级别 |
| :---: | :--- | :---: |
| **5.4.1** | 验证应用会对用户提交的文件名进行验证或直接忽略，包括 JSON、JSONP 或 URL 参数中的文件名，并在响应的 Content-Disposition 头字段中指定实际文件名。 | 2 |
| **5.4.2** | 验证提供的文件名（例如 HTTP 响应头字段或电子邮件附件中的文件名）经过编码或净化（例如遵循 RFC 6266），以保持文档结构并防止注入攻击。 | 2 |
| **5.4.3** | 验证从不可信来源获取的文件会经过防病毒扫描器扫描，以防止提供已知恶意内容。 | 2 |
