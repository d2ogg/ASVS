# V7 会话管理

## 控制目标

会话管理机制让应用即使在使用无状态通信协议（例如 HTTP）时，也能在一段时间内关联用户和设备交互。现代应用可能会使用多个具有不同特征和目的的会话令牌。安全的会话管理系统应能防止攻击者获取、使用或以其他方式滥用受害者的会话。维护会话的应用必须确保满足以下高层会话管理要求：

* 会话对每个个体都是唯一的，不能被猜测或共享。
* 当不再需要会话时，会话会失效；在不活动期间，会话会超时。

本章许多要求都与选定的 [NIST SP 800-63 Digital Identity Guidelines](https://pages.nist.gov/800-63-4/) 控制相关，重点关注常见威胁和常被利用的认证弱点。

请注意，某些会话管理机制的具体实现细节要求可在其他章节中找到：

* HTTP Cookie 是保护会话令牌的常见机制。Cookie 的具体安全要求位于“Web 前端安全”章节。
* 自包含令牌经常用于维护会话。具体安全要求位于“自包含令牌”章节。

## V7.1 会话管理文档

不存在适合所有应用的单一模式。因此，无法定义适用于所有情况的通用边界和限制。作为实现和测试的前提，必须围绕会话处理进行风险分析，并记录相关安全决策。这可以确保会话管理系统符合应用的具体要求。

无论选择有状态还是“无状态”会话机制，分析都必须完整并形成文档，以证明所选方案能够满足所有相关安全要求。还应考虑与任何正在使用的单点登录（SSO）机制之间的交互。

| # | 描述 | 级别 |
| :---: | :--- | :---: |
| **7.1.1** | 验证用户会话不活动超时时间和绝对最大会话生命周期已记录在文档中，并且与其他控制组合后是合适的；文档还应包含任何偏离 NIST SP 800-63B 重新认证要求的理由。 | 2 |
| **7.1.2** | 验证文档定义了一个账号允许多少个并发（并行）会话，以及达到最大活动会话数时的预期行为和应采取的措施。 | 2 |
| **7.1.3** | 验证所有在联合身份管理生态系统（例如 SSO 系统）中创建和管理用户会话的系统都已记录在文档中，并包含用于协调会话生命周期、终止以及任何需要重新认证条件的控制。 | 2 |

## V7.2 基础会话管理安全

本节通过验证会话令牌是否安全生成和验证，满足安全会话的基本要求。

| # | 描述 | 级别 |
| :---: | :--- | :---: |
| **7.2.1** | 验证应用使用可信后端服务执行所有会话令牌验证。 | 1 |
| **7.2.2** | 验证应用使用动态生成的自包含令牌或引用令牌进行会话管理，也就是不使用静态 API 密钥和密钥值。 | 1 |
| **7.2.3** | 验证如果使用引用令牌表示用户会话，这些令牌是唯一的，使用密码学安全伪随机数生成器（CSPRNG）生成，并具备至少 128 位熵。 | 1 |
| **7.2.4** | 验证应用在用户认证时（包括重新认证）生成新的会话令牌，并终止当前会话令牌。 | 1 |

## V7.3 会话超时

会话超时机制用于尽量缩小会话劫持和其他会话滥用的机会窗口。超时设置必须满足已记录的安全决策。

| # | 描述 | 级别 |
| :---: | :--- | :---: |
| **7.3.1** | 验证存在不活动超时机制，会根据风险分析和已记录的安全决策强制重新认证。 | 2 |
| **7.3.2** | 验证存在绝对最大会话生命周期，会根据风险分析和已记录的安全决策强制重新认证。 | 2 |

## V7.4 会话终止

会话终止可以由应用自身处理；如果由 SSO 提供方替代应用处理会话管理，也可以由 SSO 提供方处理。考虑本节要求时，可能需要判断 SSO 提供方是否在范围内，因为其中一些要求可能由提供方控制。

会话终止应导致需要重新认证，并且应在应用、联合登录（如果存在）以及任何依赖方中生效。

对于有状态会话机制，终止通常涉及在后端使会话失效。对于自包含令牌，需要额外措施来撤销或阻止这些令牌，否则它们可能在过期前仍然有效。

| # | 描述 | 级别 |
| :---: | :--- | :---: |
| **7.4.1** | 验证当触发会话终止（例如注销或过期）时，应用禁止继续使用该会话。对于引用令牌或有状态会话，这意味着在应用后端使会话数据失效。使用自包含令牌的应用需要采用某种方案，例如维护已终止令牌列表、禁止使用某个用户特定日期时间之前生成的令牌，或轮换用户级签名密钥。 | 1 |
| **7.4.2** | 验证当用户账号被禁用或删除时（例如员工离职），应用会终止所有活动会话。 | 1 |
| **7.4.3** | 验证在成功更改或移除任何认证因素后，应用提供终止所有其他活动会话的选项。这包括通过重置或恢复流程修改密码，以及更新现有的 MFA 设置。 | 2 |
| **7.4.4** | 验证所有需要认证的页面都能方便、清晰地访问注销功能。 | 2 |
| **7.4.5** | 验证应用管理员能够终止单个用户或所有用户的活动会话。 | 2 |

## V7.5 防范会话滥用

本节提供相关要求，用于降低活动会话遭到劫持或滥用的风险。这类攻击会利用用户已登录的会话及其权限，例如通过执行恶意内容，强制已认证用户的浏览器借助其会话执行某项操作。

请注意，在考虑本节要求时，应同时参考“认证”章节中针对不同等级的指导。

| # | 描述 | 级别 |
| :---: | :--- | :---: |
| **7.5.1** | 验证应用在允许修改可能影响认证的敏感账号属性前，要求完整重新认证，例如电子邮件地址、电话号码、MFA 配置，或账号恢复中使用的其他信息。 | 2 |
| **7.5.2** | 验证用户能够查看当前任意或所有活动会话，并且在至少使用一个因素重新认证后终止这些会话。 | 2 |
| **7.5.3** | 验证应用在执行高度敏感交易或操作前，要求至少使用一个因素进行进一步认证，或进行二次验证。 | 3 |

## V7.6 联合重新认证

本节与编写依赖方（RP）或身份提供方（IdP）代码的人员相关。这些要求源自 [NIST SP 800-63C](https://pages.nist.gov/800-63-4/sp800-63c.html) 中关于联合与断言的内容。

| # | 描述 | 级别 |
| :---: | :--- | :---: |
| **7.6.1** | 验证依赖方（RP）和身份提供方（IdP）之间的会话生命周期和终止行为符合文档描述，并在必要时要求重新认证，例如达到 IdP 认证事件之间的最大间隔时间时。 | 2 |
| **7.6.2** | 验证创建会话需要用户同意或明确操作，防止在没有用户交互的情况下创建新的应用会话。 | 2 |
