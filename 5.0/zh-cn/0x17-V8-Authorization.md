# V8 授权

## 控制目标

授权确保只向被允许的消费者（用户、服务器和其他客户端）授予访问权限。为执行最小权限原则（POLP），通过验证的应用必须满足以下高层要求：

* 记录授权规则，包括决策因素和环境上下文。
* 消费者只能访问其已定义权利所允许的资源。

## V8.1 授权文档

全面的授权文档对于确保安全决策被一致应用、可审计，并与组织策略保持一致至关重要。它让开发人员、管理员和测试人员能够清楚且可执行地理解安全要求，从而降低未授权访问风险。

| # | 描述 | 级别 |
| :---: | :--- | :---: |
| **8.1.1** | 验证授权文档定义了根据消费者权限和资源属性限制功能级访问和特定数据访问的规则。 | 1 |
| **8.1.2** | 验证授权文档定义了根据消费者权限和资源属性限制字段级访问（读取和写入）的规则。注意，这些规则可能依赖相关数据对象的其他属性值，例如状态。 | 2 |
| **8.1.3** | 验证应用文档定义了应用中用于作出安全决策的环境和上下文属性，包括但不限于一天中的时间、用户位置、IP 地址或设备，也包括与认证和授权相关的决策。 | 3 |
| **8.1.4** | 验证认证和授权文档定义了除功能级、特定数据和字段级授权之外，环境和上下文因素如何用于决策。这应包括被评估的属性、风险阈值以及采取的动作（例如允许、质询、拒绝、提升认证）。 | 3 |

## V8.2 通用授权设计

在功能、数据和字段层面实现细粒度授权控制，可以确保消费者只能访问明确授予给他们的内容。

| # | 描述 | 级别 |
| :---: | :--- | :---: |
| **8.2.1** | 验证应用确保功能级访问仅限具有明确权限的消费者。 | 1 |
| **8.2.2** | 验证应用确保特定数据访问仅限对具体数据项具有明确权限的消费者，以缓解不安全直接对象引用（IDOR）和对象级授权缺失（BOLA）。 | 1 |
| **8.2.3** | 验证应用确保字段级访问仅限对具体字段具有明确权限的消费者，以缓解对象属性级授权缺失（BOPLA）。 | 2 |
| **8.2.4** | 验证已按照应用文档定义，基于消费者的环境和上下文属性（例如一天中的时间、位置、IP 地址或设备）实现自适应安全控制，用于认证和授权决策。这些控制必须在消费者尝试启动新会话时应用，也必须在已有会话期间应用。 | 3 |

## V8.3 操作级授权

在应用架构的适当层级即时应用授权变更，对于防止未授权操作至关重要，尤其是在动态环境中。

| # | 描述 | 级别 |
| :---: | :--- | :---: |
| **8.3.1** | 验证应用在可信服务层执行授权规则，而不依赖不可信消费者可操纵的控制，例如客户端 JavaScript。 | 1 |
| **8.3.2** | 验证授权决策所依据的值发生变更后立即应用。如果无法立即应用（例如依赖自包含令牌中的数据），则必须具备缓解控制，以便在使用方已不再具备授权却仍执行操作时发出告警并回滚变更。注意，这种替代方案无法防止信息泄露。 | 3 |
| **8.3.3** | 验证对象访问基于原始主体（例如消费者）的权限，而不是基于任何代表其行事的中间方或服务的权限。例如，如果消费者使用自包含令牌调用 Web 服务进行认证，而该服务随后向另一个服务请求数据，则第二个服务应使用消费者的令牌作出权限决策，而不是使用第一个服务的机器到机器令牌。 | 3 |

## V8.4 其他授权考虑

授权方面的其他考虑，尤其是针对管理接口和多租户环境的考虑，有助于防止未授权访问。

| # | 描述 | 级别 |
| :---: | :--- | :---: |
| **8.4.1** | 验证多租户应用使用跨租户控制，确保消费者操作绝不会影响其无权交互的租户。 | 2 |
| **8.4.2** | 验证访问管理接口时纳入多层安全措施，包括持续的消费者身份验证、设备安全态势评估和上下文风险分析，确保网络位置或可信端点不是授权的唯一因素，尽管它们可能降低未授权访问的可能性。 | 3 |
