# V16 安全日志和错误处理

## 控制目标

安全日志不同于错误日志或性能日志，它用于记录与安全相关的事件，例如认证决策、访问控制决策，以及绕过输入验证或业务逻辑验证等安全控制的尝试。它的目的是提供高信号、结构化数据，供 SIEM 等分析工具使用，从而支持检测、响应和调查。

除非法律要求，日志不应包含敏感个人数据；任何记录到日志中的数据都必须作为高价值资产加以保护。日志记录不得损害隐私或系统安全。应用还必须能够安全地处理故障，避免不必要的信息披露或服务中断。

详细实现指导请参考参考资料章节中的 OWASP Cheat Sheets。

## V16.1 安全日志文档

本节确保对应用技术栈各层日志记录形成清晰完整的清单。这对于有效安全监控、事件响应和合规至关重要。

| # | 描述 | 级别 |
| :---: | :--- | :---: |
| **16.1.1** | 验证存在清单，记录应用技术栈每一层执行的日志记录、记录哪些事件、日志格式、日志存储位置、如何使用、如何控制访问，以及日志保留时长。 | 2 |

## V16.2 通用日志记录

本节提供要求，确保安全日志结构一致并包含预期元数据。目标是让日志在分布式系统和工具中可被机器读取和分析。

安全事件往往涉及敏感数据。如果未经审慎考虑便记录这些数据，日志本身就会被归类为敏感资产，因而需要满足加密要求和更严格的保留策略，并且可能在审计期间被披露。

因此，只记录必要内容，并像对待其他敏感资产一样谨慎对待日志数据至关重要。

以下要求建立了日志元数据、同步、格式和控制方面的基础要求。

| # | 描述 | 级别 |
| :---: | :--- | :---: |
| **16.2.1** | 验证每条日志记录包含必要元数据（例如何时、何地、谁、什么），以便在事件发生时能够对时间线进行详细调查。 | 2 |
| **16.2.2** | 验证所有日志组件的时间源已同步，并且安全事件元数据中的时间戳使用 UTC，或包含明确的时区偏移。推荐使用 UTC，以确保分布式系统中的一致性，并防止夏令时切换期间产生混淆。 | 2 |
| **16.2.3** | 验证应用只向日志清单中记录的文件和服务存储或广播日志。 | 2 |
| **16.2.4** | 验证正在使用的日志处理器能够读取并关联日志，最好使用通用日志格式。 | 2 |
| **16.2.5** | 验证记录敏感数据时，应用根据数据保护等级强制执行日志记录规则。例如，某些数据可能不允许记录，如凭据或支付详情。其他数据，例如会话令牌，可能只能以完整或部分哈希或遮蔽形式记录。 | 2 |

## V16.3 安全事件

本节定义在应用内记录安全相关事件的要求。捕获这些事件对于检测可疑行为、支持调查和履行合规义务至关重要。

本节概述应记录的事件类型，但不试图提供详尽细节。每个应用都有独特风险因素和运行上下文。

注意，虽然 ASVS 将安全事件日志记录纳入范围，但告警和关联（例如 SIEM 规则或监控基础设施）被视为范围外内容，由运维和监控系统处理。

| # | 描述 | 级别 |
| :---: | :--- | :---: |
| **16.3.1** | 验证记录所有认证操作，包括成功和失败的尝试。还应收集其他元数据，例如认证类型或使用的因素。 | 2 |
| **16.3.2** | 验证记录失败的授权尝试。对于 L3，必须包括记录所有授权决策，包括访问敏感数据时的日志记录（但不记录敏感数据本身）。 | 2 |
| **16.3.3** | 验证应用记录文档中定义的安全事件，并记录绕过安全控制的尝试，例如输入验证、业务逻辑和反自动化控制。 | 2 |
| **16.3.4** | 验证应用记录意外错误和安全控制失败，例如后端 TLS 失败。 | 2 |

## V16.4 日志保护

日志是有价值的取证材料，必须受到保护。如果日志可以被轻易修改或删除，它们就会失去完整性，并且在事件调查或法律程序中变得不可靠。日志可能暴露应用内部行为或敏感元数据，因此也是攻击者感兴趣的目标。

本节定义要求，确保日志免受未授权访问、篡改和披露，并确保日志被安全传输和存储在安全、隔离的系统中。

| # | 描述 | 级别 |
| :---: | :--- | :---: |
| **16.4.1** | 验证所有日志组件都会适当编码数据，以防止日志注入。 | 2 |
| **16.4.2** | 验证日志受到保护，防止未授权访问，且不能被修改。 | 2 |
| **16.4.3** | 验证日志会安全传输到逻辑上独立的系统，用于分析、检测、告警和升级处理。目标是确保如果应用被攻破，日志不会同时被攻破。 | 2 |

## V16.5 错误处理

本节定义要求，确保应用能够优雅且安全地失败，而不会披露敏感内部细节。

| # | 描述 | 级别 |
| :---: | :--- | :---: |
| **16.5.1** | 验证当发生意外错误或安全敏感错误时，向使用方返回通用消息，确保不会暴露栈跟踪、查询、秘密密钥和令牌等敏感的系统内部数据。 | 2 |
| **16.5.2** | 验证当外部资源访问失败时，应用仍能安全运行，例如使用断路器或优雅降级等模式。 | 2 |
| **16.5.3** | 验证应用在发生故障（包括出现异常）时能够妥善且安全地处理，避免出现失效开放（fail-open）的情况，例如验证逻辑出错后仍继续处理交易。 | 2 |
| **16.5.4** | 验证定义了“最后防线”错误处理器，用于捕获所有未处理异常。这既是为了避免丢失必须写入日志文件的错误详情，也是为了确保错误不会导致整个应用进程崩溃，引发可用性损失。 | 3 |

注意：某些语言（包括 Swift、Go，以及按照常见设计实践的许多函数式语言）不支持异常或最后防线事件处理器。在这种情况下，架构师和开发人员应使用符合相应模式、语言或框架特点的方式，确保应用能够安全处理异常、意外或安全相关事件。
